# 실사용 E2E 점검 기록 (2026-07-30)

`main` `c7d3925`에서 시작. 신규 익명 사용자로 **실제 API + 실제 Vertex** 호출만
써서 전 기능을 훑었다. DB 직접 INSERT는 추출·임베딩 큐를 건너뛰어 실사용과
달라지므로 쓰지 않았다.

## 데이터

`POST /api/memories`로 15일치(7/15~7/29)를 `occurredAt`과 함께 넣었다.
회사(매일) · 운동(어제까지 매일, 오늘 없음) · 카페(14일 만에 재등장) ·
김밥(3일 연속) · 감정(대체로 좋음/그냥, 오늘만 별로).

## 발견과 수정

### 1. 쿠키 없는 클라이언트는 매 요청마다 새 사용자를 만든다 — 미수정

`Authorization: Bearer`를 보내도 라우트는 **쿠키만** 본다. 15번 호출하니 사용자가
15명 생겼다. 브라우저는 쿠키를 들고 다니므로 실사용엔 문제가 없지만, 비브라우저
클라이언트는 기록이 조용히 흩어진다.

**미수정으로 둔다.** 지금은 본인용 브라우저 도구이고, Bearer 수용은 인증 표면을
넓히는 변경이라 별도 판단이 필요하다.

### 2. `run_regenerations`가 요청 없이도 일기를 만들었다 — 수정

주기마다 무조건 `generate_diary`를 불러, **마감 탐지가 끝나기 전에 차이 0건짜리
일기가 굳었다.** 실제로 차이 20건이 탐지됐는데 일기엔 0건이었다.
"탐지 성공을 일기 예약의 조건으로 둔다"는 앞선 수정이 이 경로로 우회되고 있었다.

→ 대기 중인 요청이 있는 사용자만 처리한다(`fetch_regenerate_requests`).
→ 재실행 결과: `run_daily`(차이 3, 서술 3) → `run_scheduled` 순서로 바뀌었고
   일기 `다른점` 섹션에 차이가 들어갔다.

### 3. 주간 리포트가 내부 수치를 노출했다 — 수정

> "최근 7일 평균 **0.29**, 해당 날 **1.00** (z=1.6)"

일별 서술에서 이미 라벨로 바꾼 결함이 주간 경로에만 남아 있었다. 게다가
`_persist_slot`이 **이미 있는 차이를 그대로 재사용**해, 규칙을 고쳐도 옛 문구가
영원히 남았다.

→ 주간 감정 설명을 공용 `emotion_label`로 바꾸고, 재사용 시에도 설명·점수를
   갱신한다(`refresh_difference_description`). 사용자의 확인·기각은 건드리지 않는다.
→ 화면 확인: "최근 감정을 남긴 7일은 주로 '그냥'이었고, 이 날은 '좋음'"

### 4. 일기의 "오늘 처음" 제목이 내용과 어긋났다 — 수정

그 목록에 부재("운동이 없네요")·재등장·감정이 함께 들어가는데 제목은 "오늘 처음"
이었다. → **"함께 찾은 것"**.

## 확인된 동작

| 기능 | 결과 |
|---|---|
| `occurredAt` 반영 | 7/15~7/29에 하루씩. `effective_at`이 제자리를 찾음 |
| 자동 파이프라인 | `run` 하나로 추출·임베딩·탐지·서술·일기·주간까지 |
| 차이 품질 | 운동 부재(3.32) · 카페 재등장(3.32) · 감정(4.91). **회사·김밥은 안 뜸** |
| 일기 | 차이가 본문에 반영됨 |
| 주간 리포트 | 7/22 블록 생성, 슬롯 2개 |
| 회고 | "카페 언제 갔지" → 원문 인용 + "이거 맞으세요?" |

### 5. (오탐) 과거 날짜가 재탐지되지 않는 것처럼 보였다 — 버그 아님

`differences`만 지우고 다시 돌렸더니 과거 차이가 안 생겼다. 큐가 이미 비어
`recalculate_if_past`가 다시 돌 일이 없었을 뿐이다. 메모를 직접 재계산하니
7/27 김밥이 `first_occurrence`로 정상 생성됐다.

**단, 예외를 `logger.warning`으로 삼키는데 CLI는 `print` 기반이라 그 로그가
보이지 않는다.** 재계산이 실패해도 조용하다.

### 6. 주간 감정 서술이 지난 날을 "오늘"이라 불렀다 — 수정

7월 22일 기록인데 "오늘은 감정을 좋음으로 기록했습니다"라고 나왔다.

원인이 둘이었다.
- 탐지 설명 자체가 `"오늘은 '좋음'"`이었다. 이 설명은 과거 날짜로도 다시
  계산되므로 날짜 중립이어야 한다 → `"이 날은"`
- 가드레일이 없었다 → `is_today`를 호출자가 넘기고, 오늘이 아닌데 "오늘"이
  들어가면 폐기한다. UTC로 비교하면 자정 경계에서 틀리므로 사용자 타임존으로
  판정해 넘긴다

→ 결과: "2026년 7월 22일에는 '좋음'을 남겼습니다"

### 7. 일반명사가 주간 슬롯으로 올라왔다 — 일부만 수정

"이번 주 처음 기록한 것"이 **"일"** 이었다(`회사 일이 많았다`).

`몸`·`길`만 불용어에 넣었다. **`일`·`집`은 그대로 둔다** — 기존에 "과잉 차단이
더 나쁘다"고 의도적으로 제외했고 그 테스트가 있다. 실사용 근거가 하나 생겼을
뿐이라 결정을 뒤집지 않았다. 사람이 판단할 항목이다.

## 남은 의심

- 발견 1(쿠키 없는 클라이언트)
- **"일"·"집" 불용어 여부** — 실사용에서 "일"이 주간 발견으로 올라왔다.
  기존 결정을 존중해 두었으니 사람이 정해야 한다.
- **재계산 실패가 조용하다** — `logger.warning`이 CLI 출력에 안 보인다.
- 엔티티 차이 설명도 `"오늘 기록에는 없음"`처럼 "오늘"을 쓴다. 감정만 고쳤다.
  과거 재탐지에서 같은 문제가 날 수 있다.
