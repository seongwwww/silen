# 일기 정화 · 오늘의 처음(recap) · 꼬리 질문 설계 스펙

> 상태: 확정(브레인스토밍 승인). 다음 단계: 구현 계획(`docs/superpowers/plans/2026-07-27-diary-recap-followup.md`).
> 계기: **실데이터 첫 완주에서 출력 품질 문제가 드러났다.** eval 골든셋은 통과했지만 실제 하루에서는 읽기 괴로운 결과가 나왔다.

## 1. 문제 — 실데이터에서 관측된 것

메모 4건(`빵빠래 먹었다` · `출근해서 놀았다` · `여친이랑 싸웠다` · `회의로 시간 날먹`)으로 첫 일기를 만든 결과:

**① "처음" 도배** — 차이 6건이 전부 `first_occurrence`라 본문이 *"~한 것도 오늘이 처음이다"* 를 반복했다. `CLAUDE.md`의 "평범한 날은 평범하게"와 정반대다.

**② 메타적 서술** — *"일기에 출근이라는 행동이 기록된 것도 오늘이 처음이다"*, *"시간이라는 단어를 기록한 것 모두 오늘이 처음이다"*. **사용자의 하루가 아니라 시스템의 기록 상태**를 서술했다. "실은"은 *내 하루에서 놓친 차이*를 보여주는 앱이지 *DB에 처음 들어온 문자열*을 알리는 앱이 아니다.

**③ 본문과 목록의 완전 중복** — 본문이 6개를 다 언급하고, 바로 아래 `다른점` 목록이 같은 6개를 반복했다.

**④ 환각** — 원문·엔티티는 `여친`인데 본문은 **`여자친구`** 로 확장했다. 일기 단계에 엔티티명 정합 가드레일이 없어 통과했다(서술 단계엔 있다).

**⑤ 감정이 묻힘** — `여친이랑 싸웠다`가 그날 가장 큰 사건인데 *"처음 등장하는 여자친구와 싸웠다"* 로 '처음'이 주가 됐다.

**근본 증거:** 차이 7건의 `description`이 전부 `이 {영문타입} 첫 등장`이고 `confidence`가 전부 `1.0`이다. **차이 간 우선순위가 없어** 6개가 동급으로 본문에 들어갔고, 영문 enum이 섞인 메타 문구가 LLM에 그대로 전달됐다.

## 2. 핵심 아이디어 — 차이의 성격에 따라 표시 경로를 나눈다

문제의 뿌리는 **성격이 다른 두 종류를 한 산문에 몰아넣은 것**이다.

| 차이 | 성격 | 표시 경로 |
|------|------|-----------|
| `first_occurrence` ("처음 등장") | **나열이 자연스러운 정보** | **오늘의 처음(recap) 섹션** |
| `freq_shift` (연속·재등장) | **이야기가 되는 패턴** | **일기 본문에 녹임** |

프롬프트 초안 §4의 모범 예시가 정확히 후자다 — *"밤에는 어제 들었던 노래에 또 손이 갔다. 이틀째다."* 이건 서사다. 반면 *"빵빠래를 처음 먹었다"* 는 목록 항목이지 서사가 아니다.

## 3. 일기 본문 정화

- **`first_occurrence` 차이를 본문에 넣지 않는다.** 일기 입력에서 제외하고 recap이 담당한다. `freq_shift`만 본문에 녹인다.
- **메타 표현 금지.** "일기에 기록된", "~라는 단어를 기록", "기록된 것도 처음" 류. 사용자의 하루를 쓰고 시스템의 기록 상태를 쓰지 않는다. 일기 가드레일 블록리스트에 추가한다.
- **엔티티명 정합 가드레일 추가.** 본문이 입력에 없는 엔티티 표현을 만들면 폐기한다(`여친` → `여자친구` 차단). 서술 단계에 있는 검사를 일기에도 건다.
- `freq_shift`가 0건이면 본문은 **메모만으로** 쓴다(지금도 그렇게 동작한다).

## 4. detector description 정화

`이 {entity_type} 첫 등장`에서 **영문 enum이 그대로 LLM에 전달**된다. 이것이 메타 표현의 씨앗이다.

- 사람이 읽는 한국어 문구로 바꾼다(예: `처음 등장`).
- **detector의 판정 로직·임계값은 바꾸지 않는다.** 문구만 바꾼다.
- `freq_shift` 문구(`최근 N일 연속 등장` 등)는 이미 사람 말이라 그대로 둔다.

## 5. 오늘의 처음 (recap)

- `/diary`의 밋밋한 목록에 **제목("오늘 처음")과 시각 구분**을 준다. 나열이 자연스러운 형식이다.
- **새 section_type을 만들지 않는다.** 이미 `diary_sections(section_type='다른점')` 목록이 recap 형태로 렌더되고 있다 — 문제는 목록이 아니라 **본문이 그걸 중복한 것**이었다. 본문에서 빼면 목록이 곧 recap이 된다.
- 다만 지금은 `다른점` 섹션이 **본문에 쓰인 차이만** 기록된다. 이를 **그날 확정된 차이 전부**로 바꾼다(본문에 안 녹은 `first_occurrence`도 recap엔 나와야 하므로).
- 항목이 0건이면 섹션 자체를 렌더하지 않는다.

## 6. 꼬리 질문 (프롬프트 초안 §6)

**목적:** 처음 등장한 것에 대해 한 번 물어 기록을 늘린다. 기록이 쌓여야 이후 detector가 의미 있는 차이를 찾는다.

- **게이트:** 그날 `first_occurrence` 중 **새 사람(person)** 이 있으면 우선 대상. 없으면 새 장소(place) → 활동(activity) 순. 아무것도 없으면 **묻지 않는다.**
- **딱 하나만.** §6의 "기본은 묻지 않음"을 지킨다. 여러 개 묻지 않는다.
- **부담 없이.** 심문조 금지("무엇을 했냐"가 아니라 "어땠냐"). 답하지 않아도 되는 톤. 가드레일로 검증한다.
- **저장:** `diary_sections(section_type='질문', difference_id=근거 차이, content=질문)`. `difference_id` 컬럼이 이미 있어 "여친 처음 등장" 차이와 연결된다.
- **생성 시점:** 일기 생성(`generate_diary`) 안에서 함께. 별도 큐·잡을 만들지 않는다.

### 6.1 답변 경로 — 답변은 새 기록이다

질문 카드를 탭하면 **기록 화면으로 이동**하며 질문이 맥락으로 보인다. 사용자는 평소처럼 메모를 남기고, **그 메모가 파이프라인에 다시 들어간다.**

- **답변 저장 스키마를 만들지 않는다.** 답이 곧 기록이며, "기록이 쌓여야 차이가 보인다"는 제품 철학과 일치한다.
- ⚠️ **URL에 질문 텍스트를 넣지 않는다.** `?section=<diary_section_id>`로 **id만** 넘기고 화면이 조회해 표시한다. 엔티티명(사람 이름 등)이 URL·히스토리·로그에 남으면 안 된다(privacy.md).
- 질문에 답하지 않고 그냥 기록해도 된다. 강제하지 않는다.

## 7. 스키마 변경

**마이그레이션 1개, CHECK 제약 한 줄:**
```sql
-- diary_sections.section_type에 '질문' 추가
-- 기존: ('오늘의한문장','본문','다른점','성취')
```
up/down 동봉. 그 외 스키마 변경 없음.

## 8. 테스트

### 8.1 단위 (LLM 없음)
- 일기 가드레일: 메타 표현 폐기 · 입력에 없는 엔티티 표현 폐기(`여친`→`여자친구`) · 기존 검사 유지.
- 일기 입력 조립: `first_occurrence` 차이가 프롬프트에서 **제외**되고 `freq_shift`만 들어간다.
- 꼬리 질문 게이트: person > place > activity 우선순위 · 대상 없으면 질문 없음 · 하나만.
- 질문 가드레일: 심문조·강요 표현 폐기, 엔티티명 정합.
- recap 섹션 UI: 항목 표시 · 0건이면 미렌더.
- 질문 카드 UI: 기록 화면 링크가 **id만** 담는다(질문 텍스트가 URL에 없음).

### 8.2 통합 (실 DB)
- `generate_diary`가 `freq_shift`만 본문 재료로 쓰고 `first_occurrence`는 recap 섹션으로 남긴다.
- 새 사람 등장 시 `질문` 섹션이 1건 생성되고 근거 차이와 연결된다.
- 대상 없으면 질문 섹션이 생기지 않는다.
- 기록 화면이 `section` id로 질문을 조회해 보여준다(타 사용자 질문은 RLS로 안 보임).

### 8.3 eval
**골든셋을 보강한다.** 이번 문제는 기존 eval을 통과하고도 실데이터에서 터졌다.
- `first_occurrence`가 다수인 날 → 본문에 "처음"이 반복되지 않는다.
- 메타 표현("기록된", "단어를") 0건.
- 엔티티명 확장 0건(`여친`→`여자친구`).
- 꼬리 질문: 하나만 · 심문조 아님 · 대상 없으면 미생성.

## 9. 범위 밖
- 의미 필터(프롬프트 초안 §2) · 추출 정제(`시간` 같은 일반명사 억제) · `confidence` 차등화.
- 답변↔질문 연결 저장(답변은 그냥 기록이다) · 질문 여러 개 · 대화형 후속.
- 통합 테스트 격리 · 워커 CLI UTF-8.

## 10. 주요 결정 요약
- **차이 성격별로 표시 경로를 나눈다**: `first_occurrence`→recap(나열), `freq_shift`→본문(서사).
- **일기 본문에서 "처음"을 뺀다.** 메타 표현·엔티티명 확장을 가드레일로 막는다.
- **detector description을 사람 말로.** 판정 로직은 불변.
- **recap은 새 섹션 타입 없이** — 기존 `다른점` 목록을 확정 차이 전부로 바꾸고 제목·시각 구분만 준다.
- **꼬리 질문은 하나, 없으면 안 묻는다.** 저장은 `section_type='질문'`(마이그레이션 한 줄).
- **답변 = 새 기록.** 전용 스키마 없음. **URL엔 id만**(질문 텍스트 금지).
- **eval 골든셋 보강** — 기존 eval을 통과하고도 실데이터에서 터졌기 때문이다.
