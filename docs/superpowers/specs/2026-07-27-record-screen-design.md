# 기록 화면(record screen) 설계 스펙

> 상태: 확정(브레인스토밍 승인). 다음 단계: 구현 계획(writing-plans).
> 핵심 원칙(기획서·frontend.md): **첫 기록 5초** · 죄책감·독려 금지 · 담담한 톤 · 상태 명시 · 접근성(44px·색만으로 전달 금지).

## 1. 목적·경계

메모를 입력해 저장하는 화면. **파이프라인의 입구**다 — 지금 백엔드(추출·detector·서술·일기)는 다 있는데 **사람이 기록할 화면이 없어 실데이터가 하나도 안 쌓인다.** 이 화면이 그걸 푼다.

**경계:** 기록 생성만. 열람·목록·일기 표시는 하지 않는다(별도 슬라이스). **순수 프론트 슬라이스** — `POST /api/memories`가 이미 완비돼 있어 백엔드 변경 없음.

## 2. 라우트·구조

- **홈 `/`** 를 기록 화면으로 교체한다(현재 Next.js 기본 스캐폴딩 제거, `app/layout.tsx` metadata를 "실은"으로). "5초" 약속상 앱을 열면 곧 입력창이어야 하며, 한 번 더 이동시키지 않는다.
- `app/page.tsx`(서버 컴포넌트) → `app/_components/RecordForm.tsx`(`"use client"`) 렌더.
- **세션 불필요** — `POST /api/memories`가 세션 없으면 **익명 세션을 자동 생성**한다(auth §6). 로그인 없이 첫 기록 가능.

## 3. 화면 (레이아웃 B — 한 줄 우선)

- 입력창 + 전송 버튼이 **한 줄**(메신저 리듬), 그 아래 작은 감정 칩 3개, "기분은 안 골라도 괜찮아요" 한 줄.
- 플레이스홀더 "오늘, 실은…". 감정 라벨은 담담하게 **좋았어요 · 그냥 · 별로**(= API의 `good`·`neutral`·`bad`).
- 감정은 **선택**이며 **토글**(다시 누르면 해제). 기본 미선택.

## 4. 입력 동작

- textarea **자동 확장**(1줄 시작 → 최대 6줄, 그 이상은 스크롤).
- **엔터 = 줄바꿈**(모바일 관례). 저장은 **전송 버튼**. 데스크톱 편의로 `Ctrl/Cmd+Enter` 저장 지원.
- 공백만 있으면 전송 버튼 **비활성**(API의 `EmptyMemoryError` 왕복 없이 즉시 차단).
- 요청 바디: `{ text, emotion? }`. `assetPaths`·`occurredAt`은 이번 범위 밖(서버가 `captured_at` 기본값 사용).

## 5. 저장 직후 (담담한 확인 + 연달아 쓰기)

- 성공 → 입력창·감정 **초기화**, "기록했어요" 짧은 토스트, **포커스 유지**로 바로 다음 기록 가능. 화면 이동 없음, 축하·독려 문구 없음.

## 6. 상태 처리 (frontend.md)

- **saving:** 전송 중 버튼 비활성. ⚠️ **`POST /api/memories`는 멱등이 아니다** — 이중 클릭이 중복 메모를 만든다. **in-flight 가드 필수.**
- **error:** 실패 시 **입력 내용을 절대 보존**(날리지 않는다) + "기록하지 못했어요. 다시 시도해 주세요" 토스트. 자동 재시도 없음.
- **offline:** `navigator.onLine`이 false면 전송 전에 안내한다(오프라인 큐잉은 범위 밖).
- loading·empty는 이 화면에 해당 없음(입력 전용).

## 7. 접근성

- textarea에 라벨(시각적 숨김), 전송 버튼 `aria-label`, 감정 칩은 **`aria-pressed`로 선택 상태 전달**(색만으로 의미 전달 금지), 터치 타깃 44px 이상, 포커스 표시.

## 8. 컴포넌트 배치 (frontend.md)

- 감정 칩은 **지금은 이 화면 전용** `app/_components/EmotionChips.tsx`. 두 번째 사용처가 생길 때 `components/common/`으로 승격한다(성급한 공통화 금지).
- 토스트는 기존 `sonner` 재사용(`<Toaster/>`가 이미 `app/layout.tsx`에 마운트됨). shadcn `Button`·`Textarea` 사용.

## 9. 테스트 (DoD = lint + typecheck + unit + integration)

- **컴포넌트 단위(jsdom):** 공백만이면 전송 불가 · 텍스트(+감정)가 POST 바디에 실림 · **이중 클릭에 1회만 전송**(중복 방지) · 실패 시 입력 보존 · 성공 시 초기화.
- `POST /api/memories` 통합 테스트는 이미 존재 → 추가하지 않는다.

## 10. 범위 밖
- 사진 첨부(Storage 업로드·`assetPaths`) · 기록 열람/목록 · 오프라인 큐잉 · 음성 입력.
- 홈의 다른 위젯(일기·차이 요약) · 파이프라인 자동 구동(스케줄 트리거) · 로그인 UI.

## 11. 주요 결정 요약
- **홈(`/`)을 기록 화면으로.** 스캐폴딩 교체, metadata 갱신.
- **레이아웃 B**(한 줄 입력 + 전송, 아래 감정 칩). 감정은 선택·토글.
- **저장 후 머무름** — 초기화 + 담담한 토스트 + 포커스 유지(연달아 쓰기).
- **중복 전송 방지**가 핵심 안전장치(POST 비멱등). 실패 시 입력 보존.
- **백엔드 변경 없음**(기존 API 재사용), 순수 프론트 슬라이스.
