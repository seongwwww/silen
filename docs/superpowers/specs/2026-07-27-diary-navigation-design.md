# 일기 날짜 이동(`/diary/[date]`) 설계 스펙

> 상태: 확정(브레인스토밍 승인). 다음 단계: 구현 계획(`docs/superpowers/plans/2026-07-27-diary-navigation.md`).
> 성격: **읽기 전용 프론트 슬라이스.** 스키마·API 라우트·워커 변경 없음.

## 1. 문제

`/diary`는 `findLatest()` — **`limit(1)`로 가장 최근 일기 하나만** 보여준다. 오늘 밤 새 일기가 만들어지면 **어제 일기는 화면에서 도달할 수 없게 된다.** 파이프라인은 계속 일기를 쌓지만 사용자는 마지막 하나만 볼 수 있다.

"똑같다고 느낀 하루에서 놓친 차이를 **돌아본다**"는 제품 컨셉에서 과거를 못 보는 것은 핵심 가치의 손실이다.

## 2. 라우팅

| 경로 | 역할 |
|------|------|
| `/diary` | **가장 최근 일기**(현행 유지 — 주 사용 흐름) + 이전/다음 이동 |
| `/diary/[date]` | 그 날짜 일기 + 이전/다음 이동 |

`/diary`를 목록으로 바꾸지 않는다. "일기를 열면 최신이 바로 보인다"는 주 흐름을 지키고, 과거 열람은 부차적 경로로 붙인다.

**두 라우트는 같은 것을 렌더한다.** 표시·상태 분기 로직을 한 곳에 모아 중복을 만들지 않는다.

**리다이렉트를 쓰지 않는다.** `/diary` → 최신 날짜로 리다이렉트하면 URL이 바뀌고 뒤로가기가 꼬인다(뒤로 → `/diary` → 다시 리다이렉트). 두 라우트가 각자 렌더하되 공통 컴포넌트를 공유한다.

## 3. 이전/다음 = "존재하는 일기로 점프"

- **날짜−1이 아니다.** 일기는 매일 있지 않다(빈 날엔 생성하지 않는다 — 일기 생성 스펙 §4). 날짜 단위로 넘기면 일기 없는 날을 계속 지나가야 한다.
- **일기가 실제 존재하는 이전/다음 날짜로 점프**한다.
- 이전(또는 다음) 일기가 없으면 그 버튼은 **비활성**한다. 사라지게 하지 않는다 — 경계에 도달했음을 알려야 한다(레이아웃도 흔들리지 않는다).

## 4. 없는 날짜 처리

- **일기 없는 날짜 → `notFound()`(404).** 앱 안에서는 이전/다음이 존재하는 일기로만 점프하므로 도달하지 않는다. 직접 URL 입력·북마크 후 삭제된 경우에만 해당한다.
  빈 상태로 처리하지 않는 이유: 기준 일기가 없으면 이전/다음 네비게이션의 기준점도 없어 화면이 애매해진다.
- **날짜 형식이 `YYYY-MM-DD`가 아니면 → 404**(예: `/diary/abc`). 저장소 질의 전에 형식을 검증한다.
- **`/diary`에 일기가 하나도 없을 때**는 기존 빈 상태 두 종을 그대로 쓴다: "아직 쌓인 기록이 없어요"(메모도 없음) / "아직 일기가 만들어지지 않았어요"(메모는 있음).

## 5. 저장소 확장 (`lib/repositories/diaryRepository.ts`)

```ts
findLatest(): Promise<DiaryView | null>                 // 기존
findByDate(date: string): Promise<DiaryView | null>      // 신규
findNeighborDates(date: string): Promise<{ prev: string | null; next: string | null }>  // 신규
hasAnyMemory(): Promise<boolean>                         // 기존
```

- `findByDate`는 `findLatest`와 **행 → `DiaryView` 매핑 로직이 동일**하다. 공통 매핑 함수로 뽑아 중복을 피한다.
- `findNeighborDates`는 기준 날짜보다 **작은 것 중 가장 큰 날짜**(prev)와 **큰 것 중 가장 작은 날짜**(next)를 구한다.
- RLS(세션 클라이언트)·잠금/삭제 메모 필터는 기존과 동일하게 적용된다. `service_role`을 쓰지 않는다.

## 6. 아키텍처

- `app/diary/page.tsx` — 최신을 찾아 공통 뷰에 위임(현행 축소).
- `app/diary/[date]/page.tsx` — 날짜 형식 검증 → 조회 → 공통 뷰에 위임, 없으면 `notFound()`.
- `app/diary/_components/DiaryNav.tsx` — 이전/다음 링크. 44px 터치 타깃, 없는 방향은 비활성.
- `DiaryArticle`·`EvidenceDisclosure`는 **변경 없이 재사용**한다.
- **스키마·마이그레이션·API 라우트·워커 변경 없음.** `eslint.config.mjs`도 `diaryRepository.ts`가 이미 예외 목록에 있어 **추가 수정 없음.**

## 7. 접근성·모바일 (frontend.md)

- 이전/다음 버튼 **44px 이상**(`min-h-11`).
- 비활성 상태를 **색만으로 전달하지 않는다** — 링크 대신 비활성 요소로 두고 `aria-disabled`를 명시한다.
- 방향을 화살표만으로 알리지 않고 **텍스트 라벨**("이전 일기"·"다음 일기")을 함께 둔다.

## 8. 테스트

### 8.1 단위 (jsdom)
- `DiaryNav`: 이전/다음 링크가 올바른 `/diary/[date]` URL을 가리킨다.
- 이전(또는 다음)이 없으면 **비활성**이고 링크가 아니다.
- 44px 터치 타깃.

### 8.2 통합 (실 DB, RLS)
- `findByDate`가 그 날짜 일기를 정확히 가져온다(섹션·근거 포함).
- **`findNeighborDates`가 빈 날을 건너뛰고 존재하는 일기로 점프한다** — 이 기능의 핵심.
- **경계**: 가장 오래된 일기에서 `prev`가 `null`, 최신 일기에서 `next`가 `null`.
- 타 사용자 일기가 이웃으로 잡히지 않는다(RLS).

### 8.3 eval
**해당 없음** — 프롬프트·모델 미변경.

## 9. 범위 밖
- 목록 화면 · 달력 UI · 무한 스크롤/페이지네이션.
- 일기 편집·확정 · 공유·내보내기.
- 스키마·API 라우트·워커 변경.

## 10. 주요 결정 요약
- **`/diary` 최신 유지 + `/diary/[date]` 추가.** 목록으로 바꾸지 않아 주 흐름을 지킨다.
- **이전/다음은 존재하는 일기로 점프**(날짜−1 아님). 빈 날을 넘기지 않게.
- **일기 없는 날짜·잘못된 형식은 404.** 기준 일기 없이는 네비게이션 기준점도 없다.
- **리다이렉트 대신 공통 컴포넌트 공유** — 뒤로가기가 꼬이지 않게.
- 없는 방향 버튼은 **비활성**(숨기지 않음), 라벨 병행, 44px.
