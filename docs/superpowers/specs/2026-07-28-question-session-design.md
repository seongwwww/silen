# 질문 세션 · 이어 쓰기 설계 스펙

> 상태: 사용자 승인. 같은 질문에 여러 번 기록하고, 원할 때만 생각 단서를
> 펼쳐 꼬리에 꼬리를 무리 없이 이어가는 프론트 슬라이스다.

## 1. 문제

꼬리 질문 카드를 누르면 기록 화면에 질문이 보이고, 저장 뒤에도 URL의
`section` 맥락은 남는다. 따라서 같은 질문에서 여러 번 기록할 수 있지만
UI가 이를 설명하지 않아 사용자는 한 번 답하면 끝나는 질문으로 받아들인다.

상사·맥주처럼 "오늘 처음"에 함께 보이는 항목도 처리 방식이 다르다.
모든 `first_occurrence`는 recap에 남지만 질문은 사람 → 장소 → 활동 중 하루
하나뿐이며, 사물은 질문 대상이 아니다. 질문을 자동으로 계속 밀어붙이면
"기본은 묻지 않음"과 죄책감 유도 금지 원칙을 해친다.

## 2. 목표

- 같은 질문에서 기록을 여러 번 남길 수 있음을 일기와 기록 화면에서 알린다.
- 저장 뒤 질문 맥락과 포커스를 유지해 바로 이어 쓸 수 있게 한다.
- 사용자가 원할 때만 세션용 생각 단서를 한 가지씩 펼친다.
- 질문에서 남긴 기록도 일반 메모로 파이프라인에 들어간다는 의미를 설명한다.
- 기록이 쌓이면 추가 엔티티와 이후 재등장·반복 패턴을 찾는 재료가 될 수
  있지만, 즉시 차이가 생긴다고 약속하지 않는다.

## 3. 질문 세션

질문 카드에서 기록 화면으로 이동한 뒤 `?section=<uuid>`가 유지되는 동안을
질문 세션으로 본다. 별도 세션 테이블이나 답변 타입을 만들지 않는다.

- 질문은 입력 위에 `"이 질문에서 이어 쓰는 중"` 라벨과 함께 고정한다.
- 안내: `"한 번에 다 적지 않아도 괜찮아요. 같은 질문에서 여러 번 이어 쓸 수 있어요."`
- 저장 성공 시 입력·감정만 비우고 질문 맥락은 유지한다.
- 질문 세션의 성공 알림:
  `"기록했어요. 더 떠오르면 이어 적어도 돼요."`
- 각 답은 기존 `POST /api/memories`로 저장되는 독립 메모다.

## 4. 부담 없는 생각 단서

자동으로 새 질문을 띄우지 않는다. 사용자가
`"다른 각도로 떠올려보기"`를 눌렀을 때만 단서 하나를 보여준다.

세션 전용 결정적 단서:

1. `"같이 떠오르는 장면이 있나요?"`
2. `"미처 남기지 않은 부분이 있나요?"`
3. `"다른 날의 기억도 떠오르나요?"`

한 번에 하나만 보여주며 이후 버튼은 `"다른 단서 보기"`가 된다. 누를 때마다
다음 단서로 순환한다. 자동 전환·진행률·완료 압박·LLM 호출은 없다.
질문 세션이 아니면 단서 UI도 없다.

## 5. 작은 차이와의 연결

질문에서 남긴 답도 평소 기록과 동일하게 큐 → 엔티티 추출 → detector로
흐른다. 한 세션의 여러 기록은 그날의 재료를 더 풍부하게 만들 수 있고,
이후 다른 날에도 관련 기록이 쌓이면 재등장·반복 패턴을 찾는 근거가 된다.

UI 문구는 이 가능성을 담담하게 설명한다:

> 이렇게 남긴 기록도 쌓여, 나중에 작은 차이를 찾는 단서가 돼요.

즉시 차이가 생성된다는 표현, 기록을 더 하라는 독려, 횟수·진행률은 쓰지 않는다.

## 6. 범위

### 포함

- `FollowUpCard`의 반복 기록 안내
- `RecordForm`의 질문 세션 라벨·안내·성공 메시지
- 세션 전용 결정적 생각 단서 3개
- 접근성(`aria-live`, 44px 버튼)과 단위 테스트

### 제외

- 답변 내용을 읽고 만드는 LLM 후속 질문
- 질문↔답변 메모 영구 연결
- 새 스키마·API payload·워커 변경
- 질문 여러 개 자동 생성, 사물 질문 대상화

## 7. 완료 기준

- 사용자가 같은 질문에서 여러 번 기록할 수 있음을 두 화면에서 이해한다.
- 저장 뒤 질문은 남고 입력만 비워져 이어 쓰기가 가능하다.
- 생각 단서는 명시적 클릭 때만 나타나며 한 번에 하나다.
- 질문이 없는 일반 기록 화면에는 관련 안내가 없다.
- lint · build · 프론트 단위 테스트가 통과한다.
