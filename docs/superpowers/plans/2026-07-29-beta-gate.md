# P1 — 스케줄링 (자동 일기)

와이어프레임 #1의 *"오늘 밤 9시, 메모를 하루 이야기로 묶어드릴게요"* 를 진짜로 만든다.
**지금 제품은 자동이라고 말하면서 사람이 CLI를 친다.** 보상 계단의 첫 칸이 수동이면
계단이 성립하지 않는다.

## P1.1 일기 시각 설정

**마이그레이션 1건**(up/down 같은 커밋):

```sql
alter table public.users
  add column diary_hour smallint not null default 21
    check (diary_hour between 0 and 23);
```

- 분 단위를 만들지 마라. 정시로 충분하다
- `/settings`에 시간 선택(기존 톤 프리셋 옆). **"몇 시에 하루를 묶어드릴까요"**
- **사용자 로컬 시각이다.** `users.timezone`과 함께 해석하고 경계 계산은
  `lib/time` 단일 출처를 거친다

## P1.2 `run-scheduled` 명령

- 현재 시각 기준으로 **각 사용자의 로컬 `diary_hour`가 방금 지난 사용자만** 골라 생성
- **멱등이 생명이다.** 스케줄러가 5분마다 돌아도 하루 1건을 넘지 않아야 한다.
  기존 `diary_generation_requests`의 `(user_id, date)` 유니크를 재사용해라 —
  **새 원장·새 큐를 만들지 마라**
- 그날 메모 0건이면 만들지 않는다(빈 날 억지 생성 금지)
- 사용자가 이미 수동으로 만들었으면 건너뛴다
- `README.md` §4에 `schtasks` 등록 예시 추가. **등록은 사람이 한다**

**테스트(필수):**
- 타임존이 다른 사용자 2명 중 **로컬 시각이 지난 쪽만** 대상이 된다
- 같은 날 두 번 돌려도 일기가 1건이다
- 메모 0건인 사용자는 대상이 아니다
- 이미 일기가 있으면 건너뛴다

## P1.3 홈 문구를 사실에 맞춘다

지금은 *"오늘 기록을 묶을 준비를 하고 있어요"* 인데 아무도 준비하지 않는다.
설정된 시각을 넣어 **"오늘 밤 9시에 묶어드릴게요"** 로 바꾼다.
**시각이 지났는데 아직 없으면** 수동 버튼을 계속 보여준다 — 실패했다고 단정하지 마라.

# P2 — 탐지 품질: 일반명사 억제

실데이터 검증에서 **"점심"이 `first_occurrence` 4.46 bits로 올라왔다.**
"김밥"은 의미가 있고 "점심"은 없다.

- 추출 단계에서 **일반명사·시간대어를 거른다**: 점심·저녁·아침·오늘·내일·주말 등
- **하드코딩 불용어 목록으로 시작해라.** LLM에게 "의미 있는지 판단해줘"를 시키지 마라 —
  탐지·추출은 결정적이어야 한다(제품 불변 원칙)
- `extraction/constants.py` 한곳에. eval 골든셋에 케이스 추가
- **과잉 차단이 더 나쁘다.** "집"·"일"은 애매하니 확실한 것만 넣어라

# P3 — 회고: 벡터 RAG 채팅 ★ 이번의 핵심

기획서 §9. 지금은 키워드 검색뿐이다. **채팅으로 물으면 기록에서 찾아 답하고,
찾은 게 맞는지 되묻는다.**

## P3.0 결정은 ADR-0004에 확정됐다 (완료)

`docs/decisions/ADR-0004-embeddings.md`가 **채택 상태**다. 아래는 그 요약이며,
**계획과 ADR이 어긋나면 ADR이 이긴다.** 실제 호출로 검증한 값이다.

| | 확정값 | 근거 |
|---|---|---|
| 임베딩 모델 | `gemini-embedding-001` | 실제 호출 확인. `models.list()`엔 안 뜨지만 동작한다 |
| **차원** | **768** (`output_dimensionality` 명시) | 기본 3072은 **HNSW 상한 2000을 넘어 인덱스를 못 만든다**(pgvector 0.8.2에서 실패 확인) |
| task type | 문서 `RETRIEVAL_DOCUMENT` / 질문 `RETRIEVAL_QUERY` | 검색 품질 |
| 거리·인덱스 | cosine · HNSW | |
| 답변 LLM | `gemini-3.5-flash` | 추출·서술과 동일 |
| 저장 구조 | `memory_embeddings` 단일 테이블, `(memory_id, user_id)` 복합 FK cascade | 폴리모픽 회피 + 임베딩 소유자가 부모와 어긋날 수 없게 |

**차원을 기본값에 맡기지 마라.** 3072로 저장하면 인덱스를 만들 수 없고, 나중에
바꾸면 전량 재임베딩이다.

## P3.0b 요청 경로 — 큐 유지 + `--watch` (완료)

앱이 Vertex를 직접 부르지 않는다. **2자산 경계를 지킨다** — 질문은 기존
`memory_jobs` 큐에 짧게 사는 요청·응답 슬롯으로 들어가고, 워커가 답한 뒤
브라우저가 인증 RPC로 가져가면서 메시지를 지운다. 대화는 저장하지 않는다.

**대신 소비 주기를 바꿨다.** 스케줄러 주기(분)로는 사람이 화면 앞에서 기다리는
답변에 늦다. `run-pending --watch`가 짧은 간격으로 큐를 돈다.

- `--watch` 없이 부르면 기존처럼 1회만 돈다(스케줄러 호환)
- 빈 큐일 때만 잠들고, 일이 밀려 있으면 곧장 다음 배치로 간다
- 배포되는 상주 서비스가 아니라 **개발 머신에서 켜 두는 루프**다
- 안 띄우면 화면은 "찾고 있어요"에 머문다. **실패라고 단정하지 마라**

## P3.1 임베딩 저장·생성

**마이그레이션 1건**(up/down):
- `memory_embeddings` — `memory_id` FK **on delete cascade**, `embedding vector(N)`,
  `model text`, `created_at`
- **HNSW 인덱스 + cosine**
- RLS: 부모 메모 소유권 경유(`supabase/README.md`의 두 형태 중 하나)
- `authenticated`(select)·`service_role`(all) GRANT

**워커:**
- 큐를 재사용한다. 엔티티 추출이 끝난 뒤 이어서 임베딩을 만든다
- **멱등:** `memory_id` 유니크. 재시도가 중복 벡터를 만들면 안 된다
- 잠긴(`is_locked`)·삭제된 메모는 **임베딩하지 않는다**
- 본문을 로그에 남기지 마라(ID·카운트만)

**백필:** 기존 메모용 `backfill-embeddings` CLI. 실 Vertex 호출이므로 **사람이 실행한다.**

## P3.2 검색 — 하이브리드

- **`user_id` 선필터 후 벡터 검색.** 교차 사용자 노출은 심각 결함이다(privacy.md)
- `is_locked = true`·`deleted_at is not null` 제외
- **벡터 + 키워드(기존 `recall.ts`) 하이브리드 후 재정렬.** 벡터만 쓰면 고유명사를
  놓친다. 키워드만 쓰면 뜻이 안 통한다
- 상위 N(기본 8)만 LLM에 넘긴다

## P3.3 채팅 — 확인형 대화

**핵심 UX:** LLM이 단정하지 않고 **"이거 맞으세요?"** 로 되묻는다.

```
사용자: 작년 이맘때 내가 고민하던 거 뭐였지
   ↓ 벡터+키워드로 후보 기록을 찾는다
답변:  7월 중순에 이 얘기를 여러 번 남기셨어요.
       ─ 7.14 "연봉보다 사람인가"
       ─ 7.21 "그냥 다닐까"
       이 얘기가 맞을까요?
사용자: 응 맞아
   ↓ 확인된 근거로 더 깊이 답한다
```

**가드레일 — 서술과 같은 강도로:**
- **실제 기록만 인용한다.** 인용문은 원문 그대로여야 하며, 검색 결과에 없는 문장을
  만들면 폐기한다(엔티티 서술의 `guardrail` 선례)
- **단정 금지.** 관찰형으로. *"~였어요"* 는 되고 *"~때문이에요"* 는 안 된다
- **조언·응원·교훈 금지.** 기존 `FORBIDDEN_PHRASES`를 재사용해라
- 근거가 없으면 **"그런 기록은 찾지 못했어요"** 라고 말한다. 지어내지 마라
- 모든 답변에 **근거 카드**(날짜 + 원문 발췌)를 붙인다. 근거 없는 문장 0%

**화면:** `/recall`을 채팅으로 바꾼다. 대화는 **저장하지 않는다**(스키마 추가 없음) —
새로고침하면 비는 게 맞다. 기록이 원본이고 대화는 조회일 뿐이다.

**상태 5종**(empty/loading/processing/error/offline)을 모두 구현해라. LLM 호출이라 느리다.

# P4 — 사진 기록

**인프라는 이미 다 있다** — 비공개 버킷 `memories`·경로 규약 `{user_id}/{uuid}.{ext}`·
Storage RLS·서버의 본인 폴더 검증(`ForeignAssetPathError`)·`assets` 테이블.
**동의 토글은 만들지 마라.** 사용자가 직접 고른 파일이라 동의를 받을 대상이 아니다.

- `/record`에 사진 첨부. **클라이언트가 로컬 Supabase Storage에 직접 업로드**한 뒤
  경로를 `POST /api/memories`에 넘긴다
- **경로 검증을 우회하지 마라.** 그게 교차 사용자 파일 누출의 유일한 방어선이다
- 업로드 실패·용량 초과·취소를 모두 처리한다. **어떤 경우에도 사용자가 쓴 글을 잃지 마라**
- 사진만 있고 글이 없어도 기록이 된다(기존 `EmptyMemoryError` 규칙 확인)
- 일기 화면·회고 근거 카드에서 **썸네일을 보여준다**(서명 URL)
- **일기·탐지·임베딩은 사진을 읽지 않는다.** MVP에 이미지 이해는 없다
- 삭제 시 Storage 파일도 지워진다 — **기존 삭제 파이프라인에 이미 있으니 확인만 해라**

# P5 — 기억 잠금 UI

**`is_locked`가 이미 탐지·검색·일기에서 제외되도록 배선돼 있는데 켤 방법이 없다.**

- 기록 목록 화면이 아직 없다 → **일기의 근거 메모**와 **회고 근거 카드**에서 잠근다
- 잠그면 **무엇이 달라지는지 한 줄로**: "잠근 기억은 검색·일기·차이 찾기에서 빠져요"
- **되돌릴 수 있다.** 삭제와 시각적으로 명확히 구분해라(색·아이콘·라벨 전부)
- 잠근 뒤 **임베딩도 검색에서 빠지는지 확인**해라(P3.2 필터)

# P6 — 공유 카드

기획서 §8. **바이럴 장치이자, 발견한 자기 모습을 남에게 보여주는 유일한 출구다.**

## P6.1 무엇을 담는가

주간 리포트의 슬롯을 그대로 쓴다(`weekly_report_highlights`):

```
        이번 주의 나
  ─────────────────────
  가장 많이 · 김밥 4번
  처음      · 그 카페
  감정      · 목요일이 달랐어요
  ─────────────────────
        실은
```

- **일기 원문·메모 본문을 절대 넣지 마라.** 기획서 §8이 명시한다.
  요약 카드만이다
- 항목별 **체크박스로 제외**할 수 있다. 기본은 전부 켬
- **미리보기**를 먼저 보여주고, 그다음에 저장한다

## P6.2 어떻게 내보내는가

**결정: PNG 다운로드만 한다. 공개 링크를 만들지 마라.**

공유 링크는 인증 없이 열리는 URL이 생긴다는 뜻이고, 그 순간 개인 기록 파생물이
인터넷에 노출된다. 기획서의 **"기본 비공개"** 를 가장 단순하게 지키는 방법은
**링크를 아예 만들지 않는 것**이다. 사용자가 파일을 받아 직접 보낸다.

- 클라이언트에서 `canvas`로 렌더 → PNG 다운로드. **서버 렌더링·업로드 없음**
- 정사각형(1080×1080). 모바일 공유에 맞는다
- 폰트는 이미 번들된 것을 쓴다. 외부 폰트를 불러오지 마라
- 리포트가 없으면 **버튼 자체를 숨긴다**

## P6.3 하지 말 것

- 워터마크에 사용자 식별 정보 금지
- "N주 연속" 같은 스트릭 문구 금지
- 공유를 유도하는 넛지·배지·보상 금지. **버튼 하나만 둔다**

## 공통 규칙

- **마이그레이션은 3건뿐**: P1.1 `diary_hour`, P3.1 `memory_embeddings`,
  (필요 시) 잠금 관련 인덱스. 그 밖에 필요해 보이면 **멈추고 보고해라**
- 모드 플래그 금지 — 동작을 주입받는다(`TodayScreen` 선례).
  데이터 출처는 경계(page)가 고른다(`app/report/page.tsx` 선례)
- 보이는 글자 = 접근성 이름(WCAG 2.5.3). 터치 타깃 44px
- 서술·회고에 내부 용어(`일기`·`활성일`·`valence`) 금지 — 가드레일이 이미 막는다
- 진행률·스트릭·죄책감 유도 금지
- 커밋은 태스크마다. push·merge는 사람이 요청할 때만
