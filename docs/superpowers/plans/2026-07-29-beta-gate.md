## 이번에 하는 것 — B1~B5

**가장 큰 거짓말부터 지운다.** 지금 제품은 *"밤에 자동으로 하루를 묶어준다"* 고 말하지만
**사람이 CLI를 쳐야 한다.** 보상 계단(Day 0 일기 → Day 3 발견 → Day 7 리포트)의
첫 칸이 수동이면 계단 자체가 없다.

## 미루는 것과 이유

| 미룸 | 이유 |
|---|---|
| **알림 + PWA** | Web Push는 service worker·VAPID·권한 흐름이 한 덩어리다. B1(자동 생성)만으로도 "아침에 열면 일기가 있다"는 성립한다. 알림은 그다음 |
| **걸음 센서 + 동의 UI** | 기획서도 "Day 0에 안 물음, 며칠 써서 가치를 느낀 뒤"라고 못박았다. 자동 일기가 먼저 돌아야 그 시점이 온다 |
| **음성(STT)** | 별도 외부 연동. 텍스트 기록이 이미 5초다 |
| **회고 RAG 대화** | `embeddings` 테이블부터 만들어야 한다. 키워드 검색이 현재 규모에선 실제로 동작한다 |
| **공유 카드** | 리포트를 사람이 며칠 써보고 "이건 남한테 보여줄 만하다"가 확인된 뒤 |
| **계정 연결** | 익명 세션으로 MVP 검증이 가능하다 |

# B1 — 일기 시간 설정 + 야간 자동 생성

와이어프레임 #1의 *"오늘 밤 9시, 메모를 하루 이야기로 묶어드릴게요"* 를 진짜로 만든다.

## B1.1 일기 시간 설정

- `users`에 일기 생성 시각이 없다. **컬럼 추가 마이그레이션 1건**(up/down 함께).
  - `diary_hour smallint not null default 21 check (diary_hour between 0 and 23)`
  - 분 단위는 만들지 마라. 정시로 충분하다
- `/settings`에 시간 선택. 기본 21시. **"몇 시에 하루를 묶어드릴까요"**
- 톤 프리셋은 이미 있다. 그 옆에 둔다

**주의:** 사용자 로컬 시간이다. `users.timezone`과 함께 해석한다(`lib/time` 단일 출처).

## B1.2 자동 생성

- CLI에 **`run-scheduled`** 추가 — 현재 UTC 시각 기준으로 **각 사용자의 로컬
  `diary_hour`가 방금 지난 사용자만** 골라 일기를 생성한다
- **멱등이 생명이다.** 스케줄러가 5분마다 돌아도 하루 1건을 넘지 않아야 한다.
  기존 `diary_generation_requests`의 `(user_id, date)` 유니크를 재사용해라.
  **새 원장을 만들지 마라**
- 그날 메모가 0건이면 만들지 않는다(빈 날 억지 생성 금지)
- 사용자가 이미 수동으로 만들었으면 건너뛴다
- `README.md` §4에 `schtasks` 등록 예시 추가 — **등록은 사람이 한다**

**테스트(필수):**
- 로컬 21시가 지난 사용자만 대상이 된다(타임존이 다른 사용자 2명으로)
- 같은 날 두 번 돌려도 일기가 1건이다
- 메모 0건인 사용자는 대상이 아니다
- 이미 일기가 있으면 건너뛴다

## B1.3 홈 문구를 사실에 맞춘다

지금 홈은 *"오늘 기록을 묶을 준비를 하고 있어요"* 라고 하지만 아무도 준비하지 않는다.
B1이 끝나면 **진짜가 된다** — 설정된 시각을 넣어 *"오늘 밤 9시에 묶어드릴게요"*.

**시각이 지났는데 아직 없으면** 수동 버튼을 계속 보여준다. 실패했다고 단정하지 마라.

# B2 — 7일 온보딩

기획서 §8. **"7일 실험 = 제품의 주 유입 장치."**

## B2.1 Day 0 첫 실행

첫 방문(기록 0건)에서 한 번만:

1. **한 줄 설명** — "똑같다고 생각한 하루에서 놓친 차이를 찾아드려요"
2. **바로 기록** — 설명을 길게 하지 말고 입력창으로 보낸다. **5초 성공이 목표다**
3. 기록 성공 후 **일기 시간·톤 프리셋**(B1.1)을 한 번 묻는다. 건너뛰기 가능

**센서 권한을 묻지 마라**(기획서 §7 [확정]). 애초에 센서가 없다.

## B2.2 Day 1~6 문구

홈의 학습 중 문구를 하루 수에 따라 바꾼다. **진행률 바·카운트다운·"N일 남았어요" 금지.**

- 활성일 1~2일: "아직 평소를 익히는 중이에요"
- 활성일 3~6일: 차이 카드가 나오기 시작한다(이미 구현됨)
- 활성일 7일 도달: 리포트로 안내 — **"7일간 이만큼 찾았어요"**

## B2.3 Day 7 연결

리포트 하단은 이미 *"다음 주엔 더 정확해져요"* 다. **끝이 아니라 시작**이라는 이 연결을 유지해라.

# B3 — 탐지 품질: 일반명사 억제

실데이터 검증에서 **"점심"이 `first_occurrence` 4.46 bits로 올라왔다.** 카드에는 안 뜨지만
"오늘 처음" 목록을 지저분하게 만든다. "김밥"은 의미가 있고 "점심"은 없다.

- 추출 단계에서 **일반명사·시간대어를 거른다**: 점심·저녁·아침·오늘·내일·주말·집·일 등
- **하드코딩 불용어 목록으로 시작해라.** LLM에게 "의미 있는지 판단해줘"라고 시키지 마라 —
  탐지·추출은 결정적이어야 한다(제품 불변 원칙)
- 목록은 `extraction/constants.py` 한곳에. eval 골든셋에 케이스 추가

**주의:** 과잉 차단이 더 나쁘다. "집"은 애매하다 — 확실한 것만 넣고 나머지는 두어라.

# B4 — 사진 기록

§12 MVP 포함. **인프라는 이미 다 있다** — `memories` 버킷·RLS·`assets` 테이블·
경로 본인 확인(`supabase/README.md` Storage 절).

- `/record`에 사진 첨부. 클라이언트가 Storage에 직접 업로드 → 경로를 `POST /api/memories`에
- **경로의 본인 폴더 검증은 이미 서버에 있다**(`ForeignAssetPathError`). 우회하지 마라
- 업로드 실패·용량 초과·취소 상태를 모두 처리한다. **사용자가 쓴 글을 잃지 마라**
- 사진만 있고 글이 없어도 기록이 된다(기존 `EmptyMemoryError` 규칙 확인)
- 일기·탐지는 사진을 읽지 않는다. **MVP에서 이미지 이해는 없다**

# B5 — 기억 잠금 UI

**`is_locked`가 이미 탐지·검색·일기에서 제외되도록 배선돼 있는데, 켤 방법이 없다.**
프라이버시가 불변 원칙인데 사용자가 쓸 수 없는 상태다.

- 기록 목록이 아직 없다 → **일기 화면의 근거 메모**와 **회고 검색 결과**에서 잠글 수 있게 한다
- 잠그면 **무엇이 달라지는지 한 줄로** 보여준다:
  "잠근 기억은 검색·일기·차이 찾기에서 빠져요"
- 잠금은 되돌릴 수 있다. 삭제와 **시각적으로 명확히 구분**해라
