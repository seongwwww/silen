# 1단계 — P4 더블체크 (`feat/photo`)

**새로 만들지 마라. 이미 커밋된 것을 의심하고 검증하는 단계다.**

`feat/photo`를 체크아웃한다(커밋 `fb56781`, `5e96be5`). 검사는 이미 통과했으니
**통과 여부가 아니라 빠진 구멍을 찾아라.**

## 반드시 확인할 것

| # | 확인 | 왜 |
|---|---|---|
| 1 | **남의 폴더 경로로 업로드가 막히는가** | Storage RLS + 서버 `ForeignAssetPathError`가 유일한 교차 사용자 방어선이다 |
| 2 | **삭제하면 Storage 파일도 사라지는가** | `worker/src/silen_worker/deletion/storage.py`가 사용자 prefix를 지운다. **통합 테스트로 확인해라**(실제 삭제 API 호출 말고) |
| 3 | **잠근 메모의 사진이 근거에서 빠지는가** | `is_locked` 필터가 사진 경로에도 적용되는지 |
| 4 | **서명 URL이 만료 뒤 안 열리는가** | TTL 10분. 만료 URL이 화면에 남으면 깨진 이미지가 된다 |
| 5 | **업로드 중 페이지를 떠나면** | 고아 파일이 남는가. 남는다면 그 사실을 보고해라(지금은 저장 시점 업로드라 안 남아야 한다) |
| 6 | **모바일 폭(375px)** | 썸네일이 가로 스크롤을 만들지 않는가 |

## 통합 테스트가 없는 곳

사진 경로에 대한 **저장소 통합 테스트가 없다.** 단위 테스트는 스텁이라
Storage RLS·경로 규약을 검증하지 못한다. 다음을 추가해라:

- 본인 폴더 업로드는 성공한다
- **남의 폴더 경로는 거부된다**
- 잠근 메모의 사진은 일기 근거에서 빠진다

`lib/repositories/*.integration.test.ts` 관례를 따르고, **자기가 만든 사용자만
정리해라**(전역 삭제 금지 — `testing.md`).

## 결과

문제를 찾으면 **고치고 커밋**해라. 없으면 "확인했고 문제 없음"을 항목별로 써라.
**전부 통과했다고만 쓰지 마라.**

# 2단계 — P5 기억 잠금 UI (`feat/memory-lock`)

`main`에서 브랜치를 딴다(P4 병합 전이면 사람에게 물어라).

**`is_locked`가 이미 탐지·검색·일기에서 제외되도록 배선돼 있는데 켤 방법이 없다.**
프라이버시가 불변 원칙인데 사용자가 쓸 수 없는 상태다.

## 무엇을 만드나

기록 목록 화면이 아직 없다. 따라서 **이미 기록이 보이는 곳**에 잠금을 붙인다:

1. **일기 근거**(`EvidenceDisclosure`) — 각 근거에 잠금 토글
2. **회고 근거 카드**(`RecallScreen`) — 같은 동작

## 규칙

- 잠그면 **무엇이 달라지는지 한 줄로**: "잠근 기억은 검색·일기·차이 찾기에서 빠져요"
- **되돌릴 수 있다.** 삭제와 **색·아이콘·라벨 전부**로 구분해라. 오탭이 나면 안 된다
- 낙관적 UI로 잠긴 척하지 마라. 실패하면 되돌리고 알려라
- API는 `PATCH`로 `is_locked`만 바꾼다. **TOCTOU 방어**: 읽은 값을 기대값으로 넘겨
  원자적 업데이트, 0행이면 409(`differences` 선례)
- 경계가 저장소를 알아야 하면 **서비스 facade**를 만들어라(`dataExportServer.ts` 선례)

## 검증 (필수)

- 잠근 뒤 `run-daily`를 다시 돌리면 **그 메모가 탐지에서 빠진다**
- 회고 검색 결과에서도 빠진다 — **임베딩 필터까지 확인해라**(P3.2)
- 잠금을 풀면 다시 들어온다
- 남의 메모는 잠글 수 없다(RLS)

# 3단계 — P6 공유 카드 (`feat/share-card`)

기획서 §8. 계획서 P6 절에 세부가 있다.

## 결정된 것 — 바꾸지 마라

- **PNG 다운로드만 한다. 공개 링크·서버 업로드를 만들지 마라.**
  링크는 인증 없이 열리는 URL이 생긴다는 뜻이고, 그 순간 개인 기록 파생물이
  인터넷에 놓인다. 기획서의 "기본 비공개"를 지키는 가장 단순한 방법이다
- **일기 원문·메모 본문을 카드에 넣지 마라.** 요약 슬롯만이다
- 클라이언트 `canvas` 렌더 → 다운로드. 정사각형 1080×1080
- 폰트는 번들된 것만. **외부 폰트를 불러오지 마라**
- 리포트가 없으면 **버튼 자체를 숨긴다**

## 담는 것

`weekly_report_highlights`의 슬롯 3종(`가장많이한것`·`처음한것`·`감정순간`).
**항목별 체크박스로 제외**할 수 있고, 기본은 전부 켬. **미리보기 먼저, 저장은 그다음.**

## 하지 말 것

- 워터마크에 사용자 식별 정보
- "N주 연속" 같은 스트릭 문구
- 공유 유도 넛지·배지·보상. **버튼 하나만 둔다**

# 각 단계 공통

## 절차

```
실패 테스트 → 최소 구현 → 리팩터 → 검사 → 커밋
```

## 검사 — 전부 통과해야 한다

```powershell
npm run check      # lint + typecheck + unit
npm run build      # ★ 반드시. Supabase select 타입 오류는 이것만 잡는다
worker\.venv\Scripts\python.exe -m ruff check worker
worker\.venv\Scripts\python.exe -m pytest worker -m "not integration"
npm run test:integration
worker\.venv\Scripts\python.exe -m pytest worker -m integration
```

**통합 테스트가 유료 API를 부르게 하지 마라.** 스텁을 주입해라(`StubEmbedder` 선례).

## 브라우저 확인 — 단계마다 직접 눈으로

`npm run dev` 후 실제로 클릭해라. **자동 검사 숫자만으로 끝내지 마라.**
회고를 건드리면 `run-pending --watch`를 띄워 둬야 한다.

**모바일 폭 375px**로도 봐라 — 가로 스크롤 없음, 탭바에 콘텐츠 안 가림.

## 디버깅

버그를 만나면 `/superpowers:systematic-debugging`:
재현 → 경계에서 증거 수집 → 단일 가설 → 최소 수정 → **회귀 테스트** → 전체 검사.

**회귀 테스트는 수정을 되돌렸을 때 실패하는지까지 확인해라.** 이번 세션에서
그 방식으로 SQL 문법 오류와 폴링 중단을 잡았다 — 둘 다 기존 단위 테스트가
전부 통과하는 상태에서 숨어 있었다.

## 커밋

`<type>(<scope>): <한국어 요약>` · 본문은 **무엇을·왜** · 마침표 없음 ·
`Co-Authored-By`는 네 것으로. **사용자 기록 본문을 커밋 메시지에 넣지 마라.**

## 보고

단계마다:

1. **안 된 것과 의심스러운 것을 먼저.** 전부 됐다고만 쓰지 마라

3. **브라우저에서 실제로 본 것** — 어떤 화면에서 무엇이 보였는지
